# 🔄 Iterations — Refy UX Design Process

This document summarizes the iterative design, prototyping, and evaluation process of the Refy application. It consolidates insights from paper prototyping and usability testing into key findings and design refinements.

---

## 1. Initial Concept

The initial concept was derived from user research and defined user stereotypes representing different financial behaviors (impulsive vs. structured spending behavior).

Based on these insights, the core idea of the application was established:

- tracking of income and expenses
- emotional tagging of financial behavior
- visualization of spending patterns over time
- support for reflection and financial awareness

Early screen concepts included:

- Account overview (home screen)
- Transaction input flow
- Calendar-based interaction view
- Forecast and analysis screen
- Settings and configuration

These early designs formed the basis for further refinement through prototyping.

---

## 2. Paper Prototyping & Testing Approach

Paper prototypes were created to validate interaction flows before implementation.

The process followed two steps:

1. Digital screen sketches to define layout and structure
2. Physical paper prototypes to simulate real user interaction

The prototypes were tested using predefined tasks covering:

- navigation between main screens
- creation and management of entries
- calendar-based interaction
- emotional tagging of expenses
- system feedback via pop-ups and modals

---

## 3. Key Usability Findings

User testing with representative participants revealed several recurring issues:

| Area            | Issue                                        | Observation                                   |
| --------------- | -------------------------------------------- | --------------------------------------------- |
| Navigation      | Calendar and overview interpretation unclear | Users initially misinterpreted screen purpose |
| Labels          | Financial terminology not always clear       | “Price” caused confusion in input context     |
| Interaction     | Navigation arrows misunderstood              | Expected behavior differed from design        |
| Pop-ups         | Multiple decision paths caused confusion     | Especially in calendar interaction flows      |
| Icons           | Forecast/mascot not immediately understood   | Weak association with function                |
| Emotional input | Emoji-based tagging partially unclear        | Interpretation required explanation           |

Overall, issues were not related to missing functionality but to unclear affordances and terminology.

---

## 4. Iterations & Design Changes

Based on test results, several targeted improvements were implemented:

- Navigation clarity improved by separating interaction controls (e.g., date navigation vs. period selection)
- Input terminology refined (e.g., “Price” → clearer financial terms like “Amount”)
- Pop-up logic simplified to reduce decision complexity
- Interactive elements visually emphasized to improve discoverability
- Forecast feature strengthened with clearer association to navigation entry points

These changes were applied across screen designs, interaction flows, and system feedback behavior.

---

## 5. Learnings

The iterative process demonstrated that most usability issues were caused by:

- ambiguous labels rather than missing functionality
- unclear visual affordances for interactive elements
- complex decision structures in early pop-up designs

Key insight:
Paper prototype testing revealed several recurring usability issues before implementation.

The final iteration improved consistency, navigation clarity, and overall system comprehensibility across different user groups.
